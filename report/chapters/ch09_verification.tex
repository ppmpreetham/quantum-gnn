\chapter{Verification and Testing}
\label{ch:verify}

\section{Philosophy: a Hostile Audit}

It is not hard to make a research pipeline look good, but it is much harder
to make it trustworthy. We therefore set up verification as a \emph{hostile}
audit, with about five hundred automated checks that each try to break one of
the claims in this report. We followed three rules.

\begin{enumerate}[label=\arabic*.]
\item \textbf{Independent answer keys.} Where we could, the expected value
comes from code or mathematics that has nothing in common with the code being
tested. Examples are a term-by-term re-derivation of the energy, an optimum
worked out by hand, an exact solver, or enumeration of every case.
\item \textbf{Floors, not snapshots.} Quality checks set a minimum level of
performance, such as ``at least 90\% exact'', instead of expecting one exact
number. A real regression then makes the suite fail, while small numerical
noise does not.
\item \textbf{Negative results stay visible.} When a check documents a
weakness, for example how often the samplers fail, we keep it and report it.
It is not removed just because the result is inconvenient.
\end{enumerate}

\section{The Shared Toolbox}

Five helper functions are used across the suite. The first generates random
connected instances and can optionally add \emph{tight} caps that sit close to
the edge of feasibility. The second is an \emph{independent energy} that works
out every term of Eq.~\eqref{eq:qubo:energy} directly, without using the
matrix. The third is brute force over all bit strings, for very small
instances. The fourth enumerates every subset of optional edges, computes the
slacks in closed form and checks connectivity directly, and it provides the
ground truth for small instances. The last is the normalised gap of
Eq.~\eqref{eq:sol:gap}.

\section{Selected Checks in Depth}

\subsection{Analytic Optima}

Section C provides the strongest checks in the suite, because their expected
answers come from a formula rather than from any code. If degree caps, the
budget, connectivity and stability are all removed, every edge becomes an
independent choice: keeping it changes the energy by $-U_e+\lambda$, so the
optimum is $\sum_e\min(0,-U_e+\lambda)$. With stability restored, each edge
chooses between dropping, at cost $\eta(x_e^{t-1})^2$, and keeping, at cost
$-U_e+\lambda+\eta(1-x_e^{t-1})^2$, so the optimum is the sum of the per-edge
minima. Brute force over the full matrix must reproduce both sums to
$10^{-9}$ on twenty random instances each. A failure here while section B
passed would mean that the matrix encodes \emph{something} consistently, but
not the intended something.

\subsection{Domain Stories}

Section G contains seven small situations where anyone can check what the
right outcome should be. If a required rover can only be reached through a
very poor \emph{bridge} link, that link has to stay, since dropping it costs a
500-point flow penalty. A weak path that is redundant has to be pruned. Out of
two identical links, the one kept in the previous cycle has to stay
(\emph{hysteresis}). A hub with a cap of 2 has to drop its worst leaf. Ten
identical links have to give the same answer every time. Under a tight budget,
two cheap links should be chosen over one expensive link. Finally, a chain of
very poor links that are all needed has to be kept in full. These cases are
easy to explain, which makes them useful when someone reviews the work.



\subsection{The Solver Audit}

Section H is set up so that every solver is judged by the same rules. Its 25
instances are small enough to have a known answer, and that answer is itself
checked: on five instances the exact linearised solve has to agree with
enumeration to within $10^{-7}$. All samplers get the real matrix, the same
warm start and the same scoring. One conversion step needs care. External
samplers use the upper-triangular form
$\sum_iQ_{ii}x_i+\sum_{i<j}Q_{ij}x_ix_j$, but our matrix is stored as a full
symmetric matrix, so the off-diagonal entries are doubled before the matrix is
passed on. If this were done wrongly, the samplers would be tested on a
different problem. The section then records the 48 to 64\% exact rates from
Chapter~\ref{ch:solvers}. For the production annealer, which is not part of
the scientific comparison, it only checks a minimum level.

\subsection{Certified Bounds on Large Instances}

On its larger instances, Section J has no known answer to compare against,
so it uses a bound instead. Taking each edge on its own, the lower of its keep
cost and its drop cost is the best that edge could ever contribute. Since
penalties are non-negative, the sum of these per-edge minima is a certified
lower bound $LB\le H^{*}$. Because $H^{*}\le H_{\mathrm{SA}}$, the quantity
$(H_{\mathrm{SA}}-LB)/\max(1,|LB|)$ is an \emph{upper bound on the true gap}.
If it is small, the solver is provably close to optimal without any exact
solve. This bound is reported next to the gap to the best-known solution.

\subsection{Regressions}

For every bug found in the external review rounds there is now a small test
that reproduces it. One example is a chain graph with connectivity constraints
and no warm start, which the annealer used to fail on. Greedy growth could not
get past the infeasible ``half a chain'' states. Starting from random spanning
trees fixed the problem, and a test keeps it from coming back.

\section{Testing the Deployments}

The two deployments carry their own tests, written in the same spirit.

\subsubsection{3D engine motion tests} Seventeen property tests check the
mathematics of Chapter~\ref{ch:engine}: angle wrapping and short-arc
interpolation; agreement of the pose integrator with the closed-form circular
arc and its exactness for straight lines; that a right turn drives the left
wheel faster; that each wheel's contact point travels exactly its rim
distance along an arc; that wheel-speed saturation preserves curvature; that
spawn layouts never overlap and are deterministic; that over 1\,800 frames at
triple speed and up to 16 rovers no two footprints ever overlap and no rover
leaves the arena; that a dense swarm never deadlocks permanently; that
corrupted frame times and planner data are rejected; and the widest-path,
parameter-snapping, advisory and bootstrap utilities.

\subsubsection{Planner service tests} Nineteen tests check the service that
connects the 3D engine to the pipeline: parameter, position, fault and
comparison validation; the shape and consistency of a planning step; the
behaviour with no links in range, an impossible degree cap and a budget below
the cheapest tree; live tuning without restarting a mission; session
capacity and idle eviction; fault delivery to every paired arm; identical
topology for the paired baselines; the solver comparison on the same matrix;
and the HTTP round trip, including rejection of malformed requests.

\subsubsection{Equivalence of instrumentation} The planner service needed a
few read-only hooks in the simulator. Their addition was verified by running
the simulator with and without them on five scenarios, including the repair
pruners and the budget-fraction mode, and checking that every cycle's
results are identical.

\section{Reproducibility Practices}

Every reported number can be regenerated provided the seeds, instance
generators and package versions are recorded with each run, and the
experiment drivers write their results incrementally so that long sweeps can
be resumed. Comparisons between pruners and between assignment policies are
always made on identical scenarios. Finally, the suite is run in full before
any change is accepted, and optional solver backends that are not installed
cause their checks to be skipped, never silently passed.
